## 3. 数据格式与标注规范

- **格式**：UTF-8 JSONL（一行一条 JSON）
- **契约**：模块接口规划 V1.2.1 Schema + V1.2.2 冻结规范
- **场景要求**：内容须属银河麒麟桌面 OS 场景（终端、办公、网络、安全、开发环境等）

### 3.1 公共字段

| 字段 | 说明 |
|------|------|
| `schema_version` | 当前 `0.1.0` |
| `case_id` | 唯一 ID，如 `PREF-0001`、`RET-0001` |
| `task_type` | 任务类型枚举 |
| `split` | `dev` / `validation` / `final_test` |
| `user_id` | 用户隔离键 |
| `scene` | 场景标签 |
| `expected` | Ground Truth |
| `tags` | 检索/分类标签 |

### 3.2 偏好提取（preference.jsonl）

- **输入**：`input_events[]`（Envelope 格式）
- **输出**：`expected.preferences[]`（PreferenceRecord）
- **关键规则**：
  - 长期偏好写入 `preferences`
  - 临时指令（「只要这一次」）→ `is_ephemeral_instruction=true` 且 `preferences=[]`
  - exact-match 比较字段：`preference_key, value, category, scope, scope_value, polarity, status`

### 3.3 知识检索（retrieval_queries.jsonl + knowledge_corpus.jsonl）

- 检索 gold 以 `memory_id` 为准，**禁止**用关键词匹配代替
- `Recall@K = |TopK ∩ gold| / |gold|`
- 须带 `user_id` 过滤，防止跨用户泄漏

### 3.4 冲突处理（conflict.jsonl）

- `relation`：duplicate / support / extend / replace / contradict / unrelated
- `strategy`：keep_old / keep_new / merge / manual_review
- 主指标：**relation 与 strategy 同时正确**（joint_accuracy）

### 3.5 精准遗忘（forget.jsonl）

- `expected_preview.should_delete_ids` / `should_keep_ids` 互斥且覆盖夹具
- execute 后目标须 `tombstoned`
- **禁止 DropCollection**

### 3.6 敏感过滤（security.jsonl）

- 核对 `blocked_or_masked` 与 `entity_type` 同时正确

完整字段说明见：`evaluation/dataset/README.md`。

## 5. 评测使用方法

### 5.1 环境准备

```bash
cd OS_Agent_Memory
python3 -m venv .venv
source .venv/bin/activate
pip install pydantic pyyaml numpy pytest
```

### 5.2 运行评测

```bash
# 日常开发（1、2 号）
python -m evaluation.run_all --split dev

# 每轮集成回归（4 号，validation 冻结）
python -m evaluation.run_all --split validation
python -m evaluation.check_freeze

# 最终盲测（赛前/验收）
python -m evaluation.run_all --split final_test
```

### 5.3 输出报告

| 文件 | 说明 |
|------|------|
| `evaluation/reports/evaluation_report.md` | 人类可读总报告 |
| `evaluation/reports/result.csv` | 机器可读指标 |
| `evaluation/reports/v0.1_<split>.txt` | 原始快照 |

### 5.4 失败归因

```bash
python -m evaluation.collect_failures --split dev
```

结果写入 `evaluation/失败案例归因表.md` 与 `evaluation/reports/failure_attribution.csv`。  
`reason_code` 须由 1、2 号确认后方可作为优化依据。
