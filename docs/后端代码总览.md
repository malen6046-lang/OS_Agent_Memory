# OS Agent Memory 后端代码总览

本文用于帮助项目成员快速理解当前后端代码。内容以当前 `memory_demo` 分支为准，
重点说明代码分层、请求流转、主要文件、数据结构、算法接入、持久化、配置和测试。

## 1. 后端当前完成了什么

当前后端已经具备：

- FastAPI HTTP 服务、Swagger 和 OpenAPI；
- Pydantic V2 请求与响应校验；
- 统一成功响应、错误响应和请求 ID；
- Service、Orchestrator、Repository 分层；
- SQLAlchemy 2.0 与 SQLite 持久化；
- 知识写入、混合检索、偏好、安全和遗忘算法的异步适配层；
- Mock、开发、麒麟三种配置入口；
- 合同、单元、持久化和 API 集成测试。

当前完整测试基线为：

```text
260 passed, 11 skipped
```

11 条跳过测试只涉及尚未安装的可选 `sentence-transformers` 后备模型。

## 2. 一次请求如何流转

```text
页面、软件、curl 或 Swagger
          │ HTTP
          ▼
app/main.py
          │ 中间件、异常处理、生命周期
          ▼
app/api/v1/routes.py
          │ 解析 HTTP，调用 Pydantic 校验
          ▼
app/services/platform.py
          │ 组织业务用例
          ├──────────────────────┐
          ▼                      ▼
MemoryOrchestrator          PlatformRepository
          │                      │
          ▼                      ▼
算法 async adapter          SQLAlchemy Repository
          │                      │
          ▼                      ▼
同步算法/麒麟 Provider       SQLite
          │
          ▼
Embedding 与向量存储
```

各层职责必须分开：

| 层 | 负责 | 不负责 |
|---|---|---|
| Route | HTTP 参数、状态码、依赖注入 | SQL、模型创建、业务算法 |
| Service | 组织一个完整业务用例 | 直接操作 HTTP |
| Orchestrator | 协调多个算法服务 | 实现 BM25、DFA 等算法 |
| Adapter | 把具体实现转换为统一协议 | 改动上层合同 |
| Repository | 数据查询、写入、事务 | 处理 HTTP |
| ORM Model | 数据库表映射 | 充当 API Schema |
| Pydantic Schema | 请求响应校验 | 直接操作数据库 |

## 4. 应用入口：`app/main.py`

`app/main.py` 创建 FastAPI 应用并管理整个应用生命周期。

启动时按顺序执行：

1. `ConfigManager().load()` 读取 YAML 和环境变量；
2. `init_db()` 创建 SQLite 表；
3. 创建 `SqlAlchemyPlatformRepository`；
4. `build_service_container(config)` 创建算法与 Provider；
5. 创建 `MemoryOrchestrator`；
6. 创建 `MemoryApiService`；
7. 启动 Embedding 和向量存储 Provider；
8. 把对象放入 `app.state`，供路由依赖获取。

应用关闭时反向关闭向量存储和 Embedding Provider，并释放数据库引擎。

该文件还负责：

- 为每个请求生成或传递 `X-Request-ID`；
- 将 Pydantic 校验错误转成统一错误结构；
- 处理业务异常、HTTP 异常和未知异常；
- 注册 `/api/v1` 路由。

## 5. HTTP 路由：`app/api/v1/routes.py`

路由函数只处理 HTTP，不直接执行 SQL，也不直接创建模型或算法。

当前主要接口：

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/v1/events/ingest` | 导入工具结果、用户行为等事件 |
| POST | `/api/v1/preferences/extract` | 从事件提取偏好候选 |
| GET | `/api/v1/preferences` | 查询当前偏好 |
| GET | `/api/v1/preferences/{key}/history` | 查询偏好历史 |
| GET | `/api/v1/preferences/{key}/versions` | 历史接口兼容别名 |
| POST | `/api/v1/knowledge/ingest` | 写入知识 |
| POST | `/api/v1/knowledge` | 知识写入兼容别名 |
| POST | `/api/v1/memory/search` | 混合检索记忆 |
| GET | `/api/v1/memory/{memory_id}` | 按 ID 查询记忆 |
| GET | `/api/v1/memory/transitions` | 查询记忆流转 |
| POST | `/api/v1/conflicts/{id}/resolve` | 处理冲突 |
| POST | `/api/v1/forget/preview` | 自然语言遗忘预览 |
| POST | `/api/v1/forget/execute` | 根据确认令牌执行遗忘 |
| POST | `/api/v1/memory/promotions/run` | 执行记忆流转 |
| POST | `/api/v1/evaluations/run` | 创建评测任务 |
| GET | `/api/v1/health` | 检查服务状态 |


## 6. Pydantic 合同：`contracts/schemas/`

合同层是模块协作边界。API、算法和后端通过这些模型理解同一份数据。

主要文件：

| 文件 | 内容 |
|---|---|
| `base.py` | 基础模型、JSON 类型、非空字符串 |
| `enums.py` | 记忆类型、状态、偏好类别、错误码等枚举 |
| `events.py` | 多源事件导入模型 |
| `memory.py` | Memory Create、Update、Response |
| `preference.py` | 偏好提取、查询和响应 |
| `knowledge.py` | 知识 Create、Update、写入结果 |
| `retrieval.py` | SearchRequest、过滤条件、检索结果 |
| `forget.py` | 遗忘预览、候选、执行和结果 |
| `evaluation.py` | 评测请求与结果 |
| `provider.py` | Provider 健康、模型和索引信息 |
| `responses.py` | 统一成功响应和错误响应 |

共同约束包括：

- 未定义字段默认拒绝；
- `confidence` 范围为 0～1；
- `top_k` 为 1～100；
- 时间必须是带时区 `datetime`；
- 枚举字段必须使用规定枚举值；
- metadata/attributes 必须可以 JSON 序列化。

## 7. Service：`app/services/platform.py`

`MemoryApiService` 是路由调用的业务入口。它把合同请求转换成完整用例，
并协调 Orchestrator 与 Repository。

主要方法：

```python
ingest_events()
extract_preferences()
get_preferences()
preference_history()
ingest_knowledge()
get_memory()
memory_transitions()
search()
resolve_conflict()
preview_forget()
execute_forget()
run_promotions()
health()
run_evaluation()
```

知识写入示例流程：

```text
KnowledgeIngestRequest
  → orchestrator.ingest_knowledge()
  → KnowledgeService 算法写 BM25/向量索引
  → 组装 KnowledgeIngestResult
  → repository.save_knowledge()
  → SQLite 保存业务记录和版本
```

## 8. Orchestrator：`app/orchestrator/`

`MemoryOrchestrator` 不实现具体算法，只调用注入的统一服务：

```python
await preference_service.extract(event)
await knowledge_service.ingest(event, preference_result)
await retriever.search(request)
await forget_service.preview(request)
await forget_service.execute(request)
```

`ports.py` 定义 Orchestrator 看到的接口，具体对象可以是 Mock、内置算法或
未来的麒麟实现。这是实现可替换性的关键。

## 9. 算法模块：`modules/`

### 9.1 知识与检索

`modules/knowledge_retrieval/` 包含：

- `knowledge_service.py`：知识写入、去重候选和冲突候选；
- `bm25.py`：关键词检索；
- `hybrid_retriever.py`：向量检索 + BM25 + RRF 融合；
- `conflict_classifier.py`：冲突关系判断；
- `memory_tier.py`：短期、中期、长期记忆层级算法；
- `service_factory.py`：一次创建共享底层组件的全部服务；
- `async_adapter.py`：把同步知识/检索算法包装成 async。

### 9.2 偏好、安全和遗忘

`modules/preference_safety/` 包含：

- `preference_service.py`：偏好提取、更新、查询和历史；
- `safety_service.py`：手机号、身份证、银行卡、邮箱、密码等检测；
- `forget_service.py`：自然语言遗忘预览和令牌确认执行；
- `async_adapter.py`：把以上同步服务包装成 async。

当前统一的五个 async 包装：

```python
AsyncKnowledgeServiceAdapter
AsyncHybridRetrieverAdapter
AsyncPreferenceServiceAdapter
AsyncSafetyServiceAdapter
AsyncForgetServiceAdapter
```

## 10. 服务工厂与容器：`app/dependencies/services.py`

`ServiceContainer` 保存应用级单例：

```text
preference_service
safety_service
forget_service
knowledge_service
retriever
embedding_provider
vector_store
```

容器负责按顺序启动 Provider，并在启动失败时回滚已经启动的组件；关闭时按
相反顺序释放资源。

`build_service_container()` 根据配置选择实现：

### 默认 Mock

```yaml
services:
  mode: mock
```

使用 Mock 偏好、知识、检索、安全和遗忘服务，适合 API 骨架测试。

### development

```yaml
services:
  mode: real
embedding:
  provider: mock
vector_store:
  provider: memory
```

使用真实 Python 业务算法，但 Embedding 是确定性 Mock，向量库是内存实现。
这是当前宿主机最完整的可运行模式。

### kylin

```yaml
embedding:
  provider: kylin
vector_store:
  provider: kylin
```

该配置目前只是入口。仍需实现并配置：

```text
KylinEmbeddingProvider
KylinVectorStoreAdapter
```

## 11. Adapter：`adapters/`

Adapter 用来隔离底层实现：

```text
统一协议
  ├── MockEmbeddingProvider
  ├── FallbackEmbeddingProvider
  └── 未来 KylinEmbeddingProvider

统一向量存储协议
  ├── MemoryVectorStore
  ├── FaissVectorStore
  └── 未来 KylinVectorStoreAdapter
```

切换 Provider 时，上层 API、Service、Schema 和算法调用方式不应改变。

## 12. Repository 与事务

`app/repositories/protocols.py` 定义：

```python
MemoryRepository
PreferenceRepository
KnowledgeRepository
AuditRepository
EvaluationRepository
PlatformRepository
```

`app/repositories/sqlalchemy.py` 提供 SQLite 实现：

```python
MemorySqlAlchemyRepository
PreferenceSqlAlchemyRepository
KnowledgeSqlAlchemyRepository
ForgetAuditSqlAlchemyRepository
MemoryTransitionSqlAlchemyRepository
AuditSqlAlchemyRepository
EvaluationSqlAlchemyRepository
SqlAlchemyPlatformRepository
```

`SqlAlchemyUnitOfWork` 负责事务边界：正常结束提交，出现异常回滚，避免只写入
一半数据。

`InMemoryRepository` 主要用于不启动 SQLite 的隔离测试，不是正式持久化方案。

## 13. ORM 与数据库表

`app/models/entities.py` 使用 SQLAlchemy 2.0 typed mapping。

| 表 | 作用 |
|---|---|
| `memory_record` | 统一记忆主记录 |
| `preference_current` | 偏好当前版本 |
| `preference_versions` | 偏好历史版本 |
| `knowledge` | 知识当前状态 |
| `knowledge_versions` | 知识历史版本 |
| `knowledge_relations` | 知识关系 |
| `conflict` | 冲突记录 |
| `forget_audits` | 遗忘执行审计 |
| `memory_transitions` | 短中长期记忆流转记录 |
| `evaluation_run` | 评测运行记录 |
| `idempotency_record` | 防止同一请求重复写入 |
| `audit_log` | 通用审计日志 |
| `vector_mappings` | `memory_id` 与向量主键关联 |

向量不会作为大型 JSON 写入知识主表。关联关系为：

```text
memory_record.memory_id
        ↕
vector_mappings.memory_id / vector_pk
        ↕
具体向量数据库
```

## 14. 统一响应和错误

成功响应：

```json
{
  "success": true,
  "request_id": "req_xxx",
  "data": {},
  "meta": {
    "elapsed_ms": 2,
    "degraded": false,
    "provider": null
  }
}
```

错误响应：

```json
{
  "success": false,
  "request_id": "req_xxx",
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "请求参数不符合接口契约",
    "retryable": false,
    "details": {}
  },
  "meta": {
    "elapsed_ms": 0,
    "degraded": false,
    "provider": null
  }
}
```

`elapsed_ms` 表示这次请求在后端消耗的毫秒数。

## 15. 配置如何加载

配置按以下优先级覆盖：

```text
configs/default.yaml
       ↓
configs/{OS_AGENT_ENV}.yaml
       ↓
OS_AGENT_* 环境变量
```

例如：

```bash
export OS_AGENT_ENV=development
export OS_AGENT_SERVICES__MODE=real
```

环境变量使用双下划线表示嵌套字段。

`AppConfig` 设置了 `extra="forbid"`，未定义的配置字段会直接报错，从而避免
拼写错误被静默忽略。

## 18. 建议阅读顺序

初次阅读代码时按以下顺序：

1. `contracts/schemas/`：先理解系统传递什么数据；
2. `app/api/v1/routes.py`：了解对外接口；
3. `app/services/platform.py`：了解每个业务用例；
4. `app/orchestrator/memory_orchestrator.py`：了解算法如何组合；
5. `app/dependencies/services.py`：了解 Mock/真实实现如何切换；
6. `modules/`：阅读具体算法；
7. `app/repositories/sqlalchemy.py`：阅读数据如何持久化；
8. `app/models/entities.py`：理解数据库结构；
9. `tests/integration/api/test_api.py`：通过完整请求示例理解全链路。

理解这条主线即可掌握当前后端：

```text
Schema 定义数据
→ Route 接收请求
→ Service 组织业务
→ Orchestrator 调算法
→ Adapter 隔离实现
→ Repository 持久化
→ 统一响应返回调用方
```
