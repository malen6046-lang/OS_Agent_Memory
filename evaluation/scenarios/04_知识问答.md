## 流程

### 1. 初次输入
运维/用户先沉淀知识（系统侧 ingest corpus），例如：

- 打开终端方法 → `mem_kb_0001`  
- 查看是否麒麟 V11 → corpus 中 os-release 条目  
- 文本向量 socket / 向量引擎路径等运维知识  

（对应 `knowledge_corpus.jsonl` 全量入库，而非单次闲聊。）

### 2. 产生什么记忆
多条 `memory_kind=semantic` 的 Knowledge/MemoryRecord，`status=active`，带 `content_text` 与 `memory_id`。  
**不**把一次性闲聊写成 preference，除非显式配置。

### 3. 第二次调用
连续提问（检索评测同款）：

1. `怎样打开麒麟系统的终端？` → 期望 `mem_kb_0001`（`RET-0001`）  
2. `怎么查看是不是麒麟V11？` → 对应版本类 gold  
3. `项目如何创建Python3.12虚拟环境？` → 对应 venv 类 gold  

评测口径：`Recall@K = |TopK ∩ gold| / |gold|`，gold 必须是 `memory_id`。

### 4. 预期结果
| 检查点 | 期望 |
|--------|------|
| 召回 | 各 query 的 `expected.gold_memory_ids` 出现在 Top-K |
| 用户隔离 | 不串用其他 `user_id` 的私有记忆 |
| 回答 | 基于命中文档生成步骤，不编造未入库命令 |
| 指标声明 | 报告中同时给出 Recall@K 与 Hit@K，不以 Hit 冒充 Recall |
