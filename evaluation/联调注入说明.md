# 评测联调注入入口（4号准备 · 配合 1/2 号）

> 4号不负责单独实现 Preference / 检索 / 冲突 / Forget 服务。  
> 本说明定义评测侧**可注入接口**，真实服务就绪后由联调方传入函数即可出分。  
> 场景「实际结果」回填仍须联调后填写日期、执行人、日志/截图。

## 快速用法

```python
from evaluation.preference_eval import run_preference_eval
from evaluation.retrieval_eval import run_retrieval_eval
from evaluation.conflict_eval import run_conflict_eval
from evaluation.forget_eval import run_forget_eval
from evaluation.security_eval import run_security_eval
from evaluation.inject_stubs import (
    wrap_preference_service,
    wrap_knowledge_search,
    wrap_conflict_classify,
    wrap_forget_preview,
    wrap_safety_detect,
)

# 将下列 None 换成真实服务适配器（见 inject_stubs.py 签名）
pref = run_preference_eval(split="dev", extract_fn=wrap_preference_service(None))
ret = run_retrieval_eval(split="dev", search_fn=wrap_knowledge_search(None))
conf = run_conflict_eval(split="dev", classify_fn=wrap_conflict_classify(None))
forg = run_forget_eval(split="dev", preview_fn=wrap_forget_preview(None))
sec = run_security_eval(split="dev", detect_fn=wrap_safety_detect(None))
```

未注入时各 `*_eval` 仍走 **baseline**，报告 `status=baseline_not_competition_claim`。

## 注入点一览

| 任务 | 函数 | 参数 | 期望返回 |
|------|------|------|----------|
| 偏好 | `run_preference_eval` | `extract_fn(case) -> list[PreferenceRecord-like dict]` | 对齐 exact-match 字段集 |
| 检索 | `run_retrieval_eval` | `search_fn(case) -> {results:[{memory_id}], meta:{elapsed_ms}}` | 带 `user_id` 隔离 |
| 冲突 | `run_conflict_eval` | `classify_fn(old, new) -> {relation, strategy, ...}` | 六类 relation |
| 遗忘 | `run_forget_eval` | `preview_fn(case) -> {should_delete_ids, confirmation_token, ...}` | token 由评测侧派生校验 |
| 安全 | `run_security_eval` | `detect_fn(text) -> {blocked_or_masked, entity_type, error_code}` | 须核对 entity_type |
| 延迟 | `run_latency_eval` | 复用检索；实机需真实 Embedding/向量 | Demo ≠ 麒麟证据 |

## 场景回填（联调后）

五个场景文件末尾「联调回填」字段：日期 / 执行人 / 日志或截图路径 / 是否与预期一致。  
机器状态见 `scenarios/scenarios.json` 的 `actual_result_status`（当前多为 `*_pending`）。
